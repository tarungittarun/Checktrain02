# R155 — opt-in Battery mode

Battery mode is a **separate Settings switch** (off by default); Appearance remains Follow system / Light / Dark and is not overwritten. Switching on uses dark native controls, paints app surfaces and system bars black, keeps legible white text and thin grey outlines, and replaces the refresh icon with a text button. Switching off recreates the original screens and returns to the saved Appearance, with no change to normal-mode data or refresh cadence.

On the tracking screen, the first glance retains source selector, provenance and freshness, delay, next stop and the full halt table. Each clock has a static A/D text cue instead of an animated arrow; the train animation, route/map canvases and colored progress bars are hidden. The last reported station is **labelled in text**, rather than indicated with a luminous train glyph. The separately attributed website past-card comparison remains a text row if already known. More/Less is immediate; connection failures remain visible without the card pulse/shake; Refresh has no spin/ripple. The two-second refresh receipt still appears over the summary as black text-on-black-border furniture. Auto · 1 min remains **explicitly opt-in** and is not silently re-enabled or disabled by Battery mode. The local freshness age still updates once a minute; a page refresh never becomes a train event.

Background optimization: the first-opening survey of all unselected websites/mirrors is skipped; the selected source is asked first using the offline cached route, followed by the existing fallback when unusable. With NTES selected, an unchanged-stop website *comparison-only* fetch is skipped in this mode (official actuals are unaffected); route enrichment/identity checks still run where required to avoid wrong or incomplete timetables. Crowd polling and automatic UI screenshots are skipped. No global animation scale or Android power-management setting is changed. Disabling Battery mode restores all of these paths on the next screen recreation.

Verification: Robolectric tests pin persisted opt-in / Appearance independence, off-mode color parity, black surface pixels, white text, static A/D clocks and textual last-report marker. The published-APK traveller Settings round-trip toggles on/off, confirms the black status bar and verifies the normal search remains usable. CI compiles all device tests and runs the existing six published-APK partitions; it does **not** dispatch the manual-only E2E workflow. Real-device OLED brightness and the optional website/fallback path still require phone confirmation. PR #3 must remain open.
