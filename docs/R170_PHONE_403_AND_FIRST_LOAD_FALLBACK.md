The prior R169 **Open browser** action did not feed the app's table. At the owner's request, R170 removes that action entirely. This release does **not** impersonate a browser, transfer cookies, run a browser challenge, hide an automated browser, or call a refusal a valid WIMT report. There is no evidence that any such tactic would produce a stable or permitted train feed. The selected `.org.in` website is independent of Google's WIMT app.

A real app-side display defect was visible in the diary: NTES had already answered with eight reported stops, yet the first-load background website refusal left the screen on the website's empty comparison table for several seconds, until the owner tapped Refresh. R170 switches the **display only** to already answered NTES on an unsuccessful first-load website check; a readable warning continues to name the **website** as the failed source, rather than misattributing HTTP 403 to NTES. The user's stored website preference is unchanged, so the next manual Refresh tries that website first (unless within its refusal pause), while Auto uses displayed NTES after fallback. A usable website answer keeps the website selected. A failed website answer with no independently answered NTES actuals does not falsely claim an official fallback. Tests cover these branches and the warning attribution. This is a UX correction, **not restored site access**.

To restore automatic `.org.in` reporting, obtain explicit site-operator permission and a supported app-access path or authorized exception. Then test one permitted phone response against the selected run's station/event semantics and the APK UI; keep PR #3 open until owner-phone acceptance. CI can prove build/tests, not operator approval or on-phone website access.
