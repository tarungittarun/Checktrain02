# R151 · Summary Box content, not the old height lock, controls its size

Owner's 28 Oct R150 screenshots at 00:52 and 00:53, train 16227, selected NTES. The website comparison hint starts underneath the headline but ends abruptly at Delay; in the next frame a yellow note is cut behind the same row. These are **real content-clipping defects**, not changed train position. The diary at `/tmp/arena-coding-uploads/opentrack-diary-20261028-005609.txt` records the website returning its Nittur 00:50 card, a timeout/fallback to NTES, and then an NTES response with last timed event TK departure 00:31. No page check is promoted to a train location.

Root cause: `compactDetailsHeight()` locked the inner ScrollView to the badge + headline (at least 124dp); `freezeSummaryHeight()` then locked the outer card, ignoring a newly visible `sourceSummary` or `note`. A refresh or comparison source could update the measured inner content while the footer remained pinned over the cut line. The result was neither a readable report nor a useful indication that the middle area scrolled.

The expanded card now fits the **laid-out full report** (badge, headline, site hint, failure note) plus the pinned title, delay/next and source/Auto controls. The measured inner content triggers a re-fit when it changes; if a note goes away it relinquishes the space instead of reserving a blank band. Its maximum is still the existing route-viewport budget. Only on a genuinely constrained screen does the middle report scroll, with a persistent visible scrollbar; the footer remains below it and the table stays a separate viewport. More/Less still animates the card size; a refresh with unchanged measured lines leaves it unchanged. No overlay was moved into the card and the 2-second check receipt remains an overlay.

The R151 sizing unit tests cover an added site hint, an added/dismissed failure note, unchanged-report refresh and cap overflow. The manual-only E2E flow now checks that visible notices are fully inside the details area or that the report is scrollable, and retains a strict no-resize assertion for unchanged content. Android CI compiles these device assertions but does **not** run the separately manual E2E workflow; phone confirmation remains necessary. PR #3 stays open and unmerged.
