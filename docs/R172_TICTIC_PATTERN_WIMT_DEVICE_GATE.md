# R172 — TicTic-style device acceptance for the selected website

The reference repository `tarungittarun/TicTic` has many focused Actions workflows. Its candidate69 qualification builds APKs and instrumentation, runs a matrix on emulators, retains device screenshots/reports, and distinguishes infrastructure failures from tested behavior. Checktrain02 already had a manual-only broad `e2e.yml` and Android JVM/Robolectric/published-APK acceptance. None of those **required an online, selected `.org.in` website report and painted site clock**; some explicitly allowed a no-report result. The user explicitly requested a focused device run now. Broad E2E stays manual-only.

This round adds `wimt-website-device-acceptance.yml`, which runs only on an explicit `[wimt-device]` test/workflow push or manual dispatch. It builds the app and instrumentation APKs from one commit, boots an online API34 emulator, installs both, enables the diary through the UI, searches for 20652, selects the independent `.org.in` website, and **fails** unless the screen paints a source-qualified past card and website-attributed clock. A browser verification page, HTTP 403, NTES fallback, undocumented `.in` cache, stale/missing run or unbooted emulator cannot pass. It captures before/after/final PNGs and XML hierarchies and an assertion log, with seven-day artifact retention. A bounded report and commit comment avoid raw session/cookie/CDN-ID publication. This is not the Google WIMT phone app or proof of a user's phone connection.

[First device run 42026847014](https://github.com/tarungittarun/Checktrain02/actions/runs/42026847014): **RED**. The APK/test APK compiled and the emulator test executed exactly one method; the UI assertion reported `Website refused request (HTTP 403)` on the selected `.org.in` source and did not show a qualified website past card. Its screenshot/hierarchy artifact exists. The original host-side parser found no readable opt-in diary, so it incorrectly reported `NO_WEBSITE_NETWORK_ANSWER` and `websiteGetCount=0`; **zero was not evidenced**. [Report-only recovery 42027893268](https://github.com/tarungittarun/Checktrain02/actions/runs/42027893268) pulled the already executed artifact without another site GET and exposed the actual assertion. The report parser is now corrected to distinguish a *visible UI 403 with diary unavailable* from a measured wire count; it must not invent a count or claim a train event. Future runs will include the bounded assertion excerpt automatically.

This test's requested number 20652 may be outside its selected active origin-run window at arbitrary CI times; even an HTTP 200 would still need a qualifying dated past card before passing. The observed 403 is independent of that run-window issue. No browser spoofing, repeated refused GET, weak assertions or false green were added. The site controls its refusal; app code cannot make an HTTP 403 into a WIMT report. Keep PR #3 open until permitted access and owner-phone validation; neither emulator evidence nor a green unit/build job substitutes for that acceptance.
