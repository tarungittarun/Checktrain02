# R169 — user-initiated real-browser view of the independent website

The long-press source selector's **Open browser** action opens `https://whereismytrain.org.in/?trainNo=<five-digit-number>` through Android's `ACTION_VIEW` and `CATEGORY_BROWSABLE`. This is the **same URL** as the selected `.org.in` website request, but the request is made by the user's installed/default browser, not by TrackTrain's `HttpURLConnection`. There is no copied User-Agent, cookie, browser fingerprint, JavaScript challenge automation, WebView session, token import or page extraction. The browser can show the site's normal page or its own verification/refusal. The app cannot guarantee that the website will let the browser through, or that a browser response can be imported into its table.

How to try it on the owner's phone: open a train's tracking screen, long-press the **Source** selector and tap **Open browser**. If the browser shows live status, this demonstrates browser access on that phone/network, **not** app HTTP access or a validated origin-run/station event. Return to TrackTrain and use **Refresh** for a separately attributed in-app request; it may still get 403, and then only labelled fallback may be shown. Browser visits do not set freshness, move the train icon, change source choice, or count as a successful Refresh.

The URL helper accepts only ASCII five-digit numbers and has unit tests for the exact same-source URL and rejection of malformed/injected identifiers. The APK's versionCode is incremented for in-place updates using the existing stable debug test signing key. This is a user-operated route to the **independent `.org.in` website**, not an integration with Google's WIMT phone app. Automatic website data in the table still requires the site's permission and a supported app-access path, followed by owner-phone acceptance; PR #3 must not be merged on the strength of a browser visit or CI alone.
