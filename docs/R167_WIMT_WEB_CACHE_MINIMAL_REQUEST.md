# R167 — different host, minimal request and contradictory-event gate

This is **not** a `.org.in` CDN workaround or a Google phone-app integration. It improves the existing, separately labelled `WIMT web cache (candidate)` diagnostic without changing the traveller's selected source or NTES actuals. PR #3 stays open.

At 2 Nov 2026 ~15:13 IST, one public read of `https://whereismytrain.in/cache/live_status?train_no=20689&date=02-11-2026&lang=en` answered JSON on the Google/Sigmoid domain **without** a copied `appVersion` or `sb_version`. It identified `start_date=02-11-2026`, YPR→SMET. Its root `lastUpdateIsoDate` was ~15:13, but the `curStn=BDVT` row listed arrival **13:35** and an `actual_departure_tm` of **12:52**, identical to its scheduled departure and *earlier* than arrival. The destination SMET row was `source=eta`. A current HTTP response therefore did **not** establish a current train position, an actual BDVT departure, or a reached destination. The fresh root timestamp and stale/contradictory station fields are separate facts. Google's [additional terms](https://support.google.com/whereismytrain/answer/10914890?hl=en) say dynamically estimated arrivals/departures may differ from actuals; an undocumented JSON field name cannot overrule that distinction.

The existing `WimtCandidate.fetch` comparison now requests **only** the five-digit train number, run date and language. It checks the returned route and origin day rather than sending copied app-version identifiers or assuming `from_day=1`. Parser changes reject a departure before its arrival, and allow already-covered day2/day3 event candidates *only when* their own update, run date and station constraints hold. Root timestamp alone still cannot revive an old point. A compact fixture of the contradictory 20689 row tests no position, no future ETA and no false departure; a separate overnight fixture checks origin-day identity. This endpoint is still undocumented, unapproved for automatic use in this repository and not asserted to be the Android app's cell-tower feed. It remains a **manual comparison probe**, not a new WIMT selector or a substitute under the selected `.org.in` label.

No further `.org.in` attempts or anti-bot challenge handling were added. This change can be evaluated by JVM tests and a genuine phone observation, but it does not prove the requested automatic Google WIMT integration works.
