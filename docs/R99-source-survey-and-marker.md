# R99 · first-load source survey and honest table position

This revision responds to the 15 Oct 2026 diary for 20652. The initial NTES result (~0.63 s) no longer suppresses the independent checks: after the official request completes, the app starts separate first-load probes for ConfirmTkt and runningstatus.in (paired cross-check), RailYatri, ixigo, whereismytrain.org.in, the WIMT **website cache**, and erail. The already-running static ConfirmTkt schedule and route probes remain separate. Each status appears in the source dropdown as it arrives. The probes do not delay the official result or silently select another source. A user selecting any source still makes a fresh request.

**Meaning of the colors:** green means *usable train-specific information from that source*, not that it is a verified actual. NTES/verified same-run actuals are labelled “reported times”; a qualified website past-card or bounded distance point is green but explicitly “unverified.” A successful HTTP response without a qualifying observation is red; an in-flight source is neutral; saved history is amber. ConfirmTkt's 11 raw rows for 20652 yielded **zero** independently corroborated actuals and remain red, not a false live feed. Ixigo's undated excerpt and RailYatri's upstream metadata similarly are not station event minutes. Runningstatus.in was 403 in the attached diary. The WIMT website is not the WIMT phone app. We still do not have five independently verified live actual feeds; adding colors does not make them exist.

The table's blue train is pinned to the last **reported stop** (or the latest actual row when the reported anchor itself has no event minute). It does not extrapolate movement from a departure flag. The age beside it is calculated from the reported arrival/departure minute on the selected run; a mere HTTP or page-update clock never resets passage age. An undated website past-card claim is amber and labelled as the site's claim. Only a bounded, route-checked source distance claim can place the amber WIMT-web marker within a leg. That is *not* GPS or a verified actual. Without such evidence, no fractional between-station train appears. Local marker age updates every 30 seconds without network activity. Selected sources without qualified rows show a timetable, not NTES actuals attributed to that source.

Manual Refresh shows a brief latency/official-feed-age receipt; it recentres on a reported marker (including an unchanged anchor). If there is no supported reported marker, it does not scroll to a guessed position. The separate source-summary line and station-table notes have been shortened; row times continue to distinguish scheduled, actual, estimated, and site-claimed values. Source investigation and installed-phone comparison remain open; PR #3 must stay unmerged until the user approves the installed APK.
