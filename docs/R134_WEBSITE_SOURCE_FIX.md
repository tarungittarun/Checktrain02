# R134 · Keep a successful selected website visible without inventing train movement

Owner diary: `opentrack-diary-20261019-093444.txt` (245 local lines, 19 October 2026, train 20652). At 09:29:19 the selected whereismytrain.org.in request hit DNS failures; a two-minute-old cached HTML body was **not** a new answer and an NTES fallback was appropriate. Later selected requests returned **network answers**, not failures: 09:29:42 showed an ADHL 09:27 site past-card claim; 09:31:45 and 09:33:48 showed HVL 09:31 and 13 site past-card rows. The app still said `refresh ... failed (comparison); fallback=...` after these successes, filled the selected-source table with timetable dashes and repeatedly switched to NTES/runningstatus.in. The diary does not prove HVL was the train's present physical location; its page-update label is **not** a passage time.

## Correction

- A selected website response with a parsed, eligible past-card report and an actual network answer is a **usable comparison**. It does not fail solely because the source state's name is `comparison`; manual and opt-in one-minute Auto keep the website selected. A timeout/cache-only answer or an unparseable/unsupported page may still fall back to a working source. NTES remains its own independent source and is not silently attributed to the site.
- When this website is selected, qualified past-card arrival/departure clocks are printed **within the matching station row on the route rail**, marked amber `Web claim ↘… ↙… · run date inferred`. Validated static-map intermediate past-card claims are marked `Web` on expanded points, including arrival-only claims without fabricating a halt or a departure. Selecting a different source removes the Web row annotations. The top card counts and names the claims; refresh feedback distinguishes a website answer from a connection failure.
- The site's public page has no selected origin-date selector. The run association remains inferred from the current timetable, not asserted by the page. Claims remain out of primary `ACTUAL` cells, the train marker, verified delay and next-stop ETA. Scrolling to the most recent website row is **not** locating a train. An unchanged claim/page-clock change never becomes a new movement event.
- No identifier spoofing, phone-app impersonation, access-control workaround or unverified provider permission is used. The website is not the Google Where Is My Train phone app.
