# R150 · stable floating Refresh, focus the last reported locomotive

The owner's 28 Oct 00:23–00:29 diary is from R149 (`1.0.77-r149`), run of 27 Oct, selected website. It recorded repeat refreshes with the same last mapped KIAT 00:21 and then a new mapped TK/Tumkur past card 00:28, revised to 00:27. The website's page clock changed during some checks without a newer station event. A manual tap should focus the *last source-reported logo* whether the event changed or not; it must not turn the page-update clock into movement. If there is no qualified logo, it must not scroll to an invented train position.

Two UI regressions: R149 attached `avoidClocks()` to every RecyclerView `onScrolled`, so a button placed at an edge moved as route clocks passed underneath. This callback is gone. Explicit drag/drop still avoids the clock cells visible at drop time, and the button is re-clamped only when the root changes size (rotation), not on scrolling or same-size relayout. In the Refresh handler `focusAfterRefresh` was always set `false`; completion therefore never scheduled the existing `focusCurrentLeg()` path. Manual refresh now requests focus, while opt-in Auto leaves the user's scroll alone. Focus waits for both the network check and the latest AsyncListDiffer route commit, then waits for the first pre-draw of the requested anchor row before centering the actual drawable (halt marker or mapped intermediate locomotive). A failed request with a retained report still focuses that report; no timed source event means no logo to focus. Stale posts from older taps cannot win over a new request.

E2E's existing manual-refresh flow now asserts a visible logo when a source-reported headline is present, including the inline-leg marker, and refuses a logo on a timetable-only outcome. The workflow remains manual-only, as the owner requested in the previous round; merely editing its assertions does not dispatch it. The Android workflow covers compilation, source contracts and rendered regressions. PR #3 remains open for real-phone confirmation.
