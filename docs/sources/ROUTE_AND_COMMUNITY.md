# Supporting inputs · route maps, offline timetable and traveller relay

These can add **static geography or explicit human reports**. None converts a website response clock into a measured moving-train position. Primary code: `remote/RailGeoRoute.kt`, `remote/OfflineCorridorMap.kt`, `v2/mirror/ConfirmTktSchedule.kt`, `v2/crowd/NtfyRelay.kt`, `v2/crowd/StopReport.kt`, `domain/RouteBetween.kt`.

| Input | Wire/fields | Used; not used |
| --- | --- | --- |
| RailGeo | `GET https://enquiry.indianrail.gov.in/ntes/RailGeo?action=getTrainSchedule&trainNo=…&trainStartDate=…` (IST-formatted run day; query assembled in `LiveViewModel`); parser extracts in-order codes and requires every independently dated official halt/endpoints. A phone trial received a maintenance notice rather than a usable route. | If valid, extra station dots/names; new points have no assumed halt status or reported clock. Not a current location, live km or independent stop actual. |
| ConfirmTkt/erail maps | Embedded dated-checked `Schedule` JSON and erail name-code list; independent static sources as described in [mirror pages](MIRROR_PAGES.md) and [erail](ERAIL.md). | Route expansion and cross-checking only; km values from two maps can disagree and must not be mixed as one scale. |
| Offline timetable / historical corridor | Bundled reference and optional 16227 historical corridor, each leg checked against selected current halt order and distances. | Search/`Sch`/fallback rail dots; historical passage estimates never written to actual or current GPS. |
| User-configured endpoint | `remote/LiveProvider.kt#OverrideProvider` uses a **user-supplied** HTTP URL template; substitutes `{trainNo}`, `{date}`, `{dateCompact}`, `{srcCode}`, `{dstCode}` and GETs a `SnapshotCodec`-compatible JSON snapshot. The returned train number is checked and a cached HTTP body is marked cached. | A format adapter for an endpoint supplied by the user, **not a connected named provider** or a permission/accuracy endorsement. The current code checks train identity; users must assess the endpoint's date, route, auth and provenance themselves before trusting it. |
| ntfy.sh traveller relay | Explicit opt-in traveller report POST to public `ct-<train>` topic; poll GET `/ct-<train>/json?poll=1&since=30m&_=<cache-buster>`. JSON envelope contains event/time/message; report contains train, station code, kind, rail minute and reported-at clock. | Fresh, validated reader lines, separate crowd attribution and optional station-time evidence under its gates. It is **user-submitted**, not CRIS/NTES; topic can be empty or unreachable, and an HTTP publish success does not guarantee every poll returns it. No continuous auto GPS feed, cryptographic origin authentication or guaranteed platform report. |

**No magic query:** `RailGeo` requests a route, ntfy polls reports, static timetables answer planned km. None can supply a site-observed `1 km to NYH` just by adding a parameter. A candidate table entry for UTS ticketing or IRCTC booking must not be promoted to an actual running-status feed merely because it belongs to an Indian Railways organisation.
