# R128 · keyboard, sorting, and source-event trust · 18 Oct 2026

- [x] **Priority: stale BDVT / purported SMET arrival.** Separate three clocks: the selected source's **reported station-event minute**, its page/feed update time, and this device's response/check time. A page updated at 13:40 does **not** prove movement at BDVT at 13:40, nor prove arrival at SMET at 13:27. Headline now says **Last [source] report … · now unknown**; the event time/age is shown separately. Site claims remain attributed and never become phone-app telemetry or confirmed NTES actuals. Source model no longer calls the page-check age the train-event age. Without a dated, run-matched SMET event from an available feed, the app must *not* fabricate an SMET arrival; it reports position unknown after the last observed stop.
- [x] An event **25 minutes old or older** turns the event-age chip, report badge/locomotive red; repaint on the local 30-second age tick, **without moving the marker**. Unknown future/undated event times have unknown freshness, not a recently updated page-clock age. Unit tests pin the exact 25-minute boundary and do not equate the site-update time with an event.
- [x] Response animation stacks `Took: N.N sec`, `Freshness: [event age / unknown]`, and `Checked: HH:mm:ss`. A missing source-update clock no longer produces `At: —` or masquerades as movement.
